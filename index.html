01

BTCFi 파트너 입출금 흐름 개발

BTCFi Partners · Hashport / DJT

사내 컨트랙트 팀의 금융 전략과 파트너 요구사항에 맞춰 JPYC 스테이블코인의 예치·인출·수익 청구를 제공하는 B2B Web3 제품

문제

DJT 지갑은 요청을 board에 제출한 뒤 승인자가 온체인 거래를 실행하는 조직형 지갑입니다. 동기식 RPC 응답을 전제한 기존 입금 흐름으로는 지원할 수 없었습니다.

판단

intent·webhook 해법은 추적에는 유리하지만 endpoint·검증 계층과 기존 흐름의 변경이 컸습니다. EIP-5792 client id에 processId를 포함하고 지갑 상태를 조회하는 프론트엔드 중심 방식을 제안했습니다.

적용과 한계

명시적 실패가 아니면 process를 유지하고, 완료 뒤 서명·제출을 이어가도록 순서를 바꿨습니다. active process와 AA 잔액을 기준으로 재진입도 지원했습니다. Hashport에서는 WebView 구현과 파트너 커뮤니케이션을 맡았습니다.

02

Bifrost Explorer 테이블 성능 개선

Bifrost Explorer

Blockscout을 fork해 운영하는 사내 블록·트랜잭션·토큰 탐색기. 입사 후 유지보수, 기능 개선과 upstream 오픈소스 업데이트 반영을 담당

문제

blocks·transactions·tokens 첫 화면은 실시간 데이터와 함께 시간 계산, 막대 차트, 이미지 등 비용이 큰 행을 렌더링했습니다. 최초 표시가 느리고 Lighthouse 점수도 낮았습니다.

검토

가상화를 먼저 적용했지만, 행 자체의 렌더링 비용이 커 스크롤 때 재렌더링과 빈 화면이 더 자주 보였고 최초 표시도 크게 나아지지 않았습니다. 이미 그린 행을 유지하는 점진 렌더링으로 바꿨습니다.

구현 및 결과

초기에는 최대 10개와 여유 5개 행만 렌더링하고, 나머지는 infinite scroll과 부분 skeleton으로 이어 보이게 했습니다. 고비용 UI는 지연 로딩하고 WebSocket 이벤트는 30초 단위로 묶어 반영했습니다. 로컬 Lighthouse 최저 점수는 45에서 91로 올랐습니다.

03

Pockie WebView·BFF 개발

Pockie · BTCFi / Swap

Pockie 지갑의 모바일·Chrome Extension 환경에서 BTCFi와 Swap 기능을 제공하는 WebView 제품

멀티 환경 WebView

공통 UI bundle을 별도로 배포하고 모바일·Chrome Extension에서 불러왔습니다. postMessage와 Jotai external store로 지갑 상태와 거래 내역을 저장·동기화했습니다.

BFF 경계

여러 외부 API와 RPC 호출이 프론트엔드에 흩어져 비즈니스 로직과 캐시 관리가 복잡했습니다. 동료와 endpoint·디렉터리·캐시·에러 모델을 협의하고, 화면 단위로 조합할 호출을 NestJS BFF로 옮겼습니다.

구현 범위

BTCFi 대시보드 BFF와 Swap BFF 구현을 맡았습니다. 모바일 stack view의 상태 반응과 페이지 전환을 조정했고, 신규 WebView에서는 관리할 endpoint와 의존 지점이 줄어 디버깅이 수월해졌습니다.
